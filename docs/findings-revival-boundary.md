# 調査: 引き剥がされるブロブの点数の境界は、n・k・バッチで変わるか

実施日: 2026-11-13 / 計測コード: `56d8ece`（新しい 5 実行とも `repo_dirty: false`、公式ソースはピン留めの SHA と一致）/ 4 スレッド / **品質専用の診断**（日中に実行。時間は記録していない）

[findings-revival-lowthr.md](findings-revival-lowthr.md) では、点の少ないブロブの唯一の重心が、自分のブロブの点をすべて受け取っていても、判定の時点で質量がほぼゼロになることを確認した。対象は Medium（n=200,000、k=1,024）の指数 1.3 で、境界は学習点約 30 点だった。この境界はほかの n・k・バッチで確かめていなかった（同文書の結論 4）。

当初の仮説は「1 バッチに入る点数の期待値（点数 × B/n）で決まる」だった。本調査ではこの仮説を確かめた。

## 方法

- `diagnose_revival.py` に `--ntrain` / `--ntest` / `--k` の上書きを加えた（`benchmark.py` と同じ。上書きした値は `metadata.json` の `settings_overrides` に記録する）。この変更を先にコミットしてから計測した。
- 共通の条件:
  - imbalanced（指数 1.3）、d=64、5 シード、e-means++、1 / 3 / 10 エポック。
  - 閾値 0.01 と 0（復活なし）。`--snapshots` で判定ごとに全重心を記録した。
  - Lloyd++ の参照は省いた（`--kmeans-niter 0`）。e-means の学習には影響しない。
  - 公式コードは改変していない。判定を止める改変（`--warmup-checks`）も使っていない。
- 次の 5 条件を新たに実行し、既存の `rev_low_imb13`（n=200,000、k=1,024）と並べた。

| 実行 | n | k | バッチ則 | ねらい |
|---|---|---|---|---|
| `rev_bnd_n50k_k256` | 50,000 | 256 | throughput（auto） | n/k を Medium と同じにする（対照） |
| `rev_bnd_n100k` | 100,000 | 1,024 | throughput（auto） | k を固定して n を変える |
| `rev_bnd_n400k` | 400,000 | 1,024 | throughput（auto） | 同上 |
| `rev_bnd_n800k` | 800,000 | 1,024 | throughput（auto） | 同上 |
| `rev_bnd_quality` | 200,000 | 1,024 | quality（明示） | バッチを約 8 分の 1 にする |

公式のバッチ則と初期ステップ（`runs.csv` に記録された値）:

| 実行 | B（1 / 3 / 10 エポック） | B/n | α0 | 判定の回数 |
|---|---|---|---|---|
| n=50k・k=256 | 1,024 / 2,048 / 8,192 | 2.0 / 4.1 / 16.4% | 0.252 / 0.418 / 1.000 | 9 / 15 / 14 |
| n=100k | 2,048 / 4,096 / 16,384 | 2.0 / 4.1 / 16.4% | 0.181 / 0.301 / 0.924 | 9 / 15 / 14 |
| n=200k（既存） | 4,096 / 8,192 / 32,768 | 2.0 / 4.1 / 16.4% | 0.248 / 0.412 / 1.000 | 9 / 15 / 14 |
| n=400k | 8,192 / 16,384 / 65,536 | 2.0 / 4.1 / 16.4% | 0.339 / 0.563 / 1.000 | 9 / 15 / 14 |
| n=800k | 16,384 / 32,768 / 65,536 | 2.0 / 4.1 / 8.2% | 0.463 / 0.769 / 1.000 | 9 / 15 / 26 |
| quality 則 | 512 / 1,024 / 4,096 | 0.26 / 0.51 / 2.0% | 0.038 / 0.063 / 0.194 | 78 / 117 / 98 |

公式のバッチ則（B ∝ k^0.13 · n^0.88 · T^0.81 を 2 のべき乗に丸める）では、n・k を変えても B/n はほとんど変わらない。B/n を大きく変えるのは、エポック数とバッチ則（quality は throughput の 8 分の 1）である。一方、初期ステップ α0 は n とともに大きくなる（Equation 6 の n^−0.45 · B^0.90 による）。

### 集計の定義

[findings-revival-lowthr.md](findings-revival-lowthr.md) と同じ定義を使った。「単独」は、閾値 0 の学習で全判定を通じて同じブロブの唯一の重心だった重心を指す。「一度でも下回る」は、そのような重心の質量 / 平均が、どれかの判定で各閾値を下回ったことを指す。本調査で加えた量は次のとおり。

| 量 | 定義 |
|---|---|
| r50 | 単独の重心について、「一度でも下回る」を log（ブロブの学習点数）のロジスティック回帰で当てはめ、下回る確率が 50% になる学習点数。条件・エポックごとに 5 シードをまとめて当てはめた |
| 最初の判定で下回る | 最初の判定（5 回目の更新の後）の時点で、質量 / 平均がすでに 0.01 未満だった割合 |

集計は `results/<run>/snapshots.csv`（Git 管理外）から、pandas を使う一時スクリプトで行った（pandas は依存に含めていない）。下の表の値は、どれもレポートの `runs.csv` には載っていない。

## 結果 1: 境界は点数で一定ではなく、1 バッチの期待点数でも決まらない

閾値 0 の学習での r50（学習点数。1 / 3 / 10 エポック）:

| 実行 | 0.001 未満 | 0.01 未満 | 0.02 未満 |
|---|---|---|---|
| n=50k・k=256 | 8.4 / 6.4 / 8.3 | 11.0 / 10.6 / 10.2 | 13.4 / 14.1 / 11.6 |
| n=100k | 5.5 / 4.0 / 4.5 | 7.6 / 6.8 / 8.0 | 9.1 / 8.4 / 9.7 |
| n=200k（既存） | 6.6 / 6.0 / 7.7 | 10.3 / 10.6 / 10.6 | 13.7 / 14.2 / 11.9 |
| n=400k | 10.4 / 9.9 / 9.8 | 16.6 / 18.2 / 12.1 | 22.6 / 24.8 / 19.7 |
| n=800k | 14.5 / 17.0 / 23.6 | 28.0 / 32.8 / 31.3 | 39.2 / 44.0 / 46.5 |
| quality 則 | 40.7 / 22.0 / 8.3 | 43.9 / 28.3 / 15.5 | 48.4 / 33.0 / 19.8 |

18 構成（6 実行 × 3 エポック）を通じた r50（0.01 未満）の開き（最大 / 最小）を、正規化のしかたごとに比べた。

| 正規化 | 最大 / 最小 | log の標準偏差 |
|---|---|---|
| 学習点数そのもの | 6.5 倍 | 0.57 |
| × B/n（1 バッチに入る点数の期待値） | 22.8 倍 | 1.00 |
| × B/(n·α0) | 3.5 倍 | 0.39 |

- **当初の仮説「1 バッチの期待点数で決まる」は支持されなかった。** この正規化は最もばらつきが大きい。既存の n=200k だけを見ても、エポック数で B/n が 8 倍変わるのに、r50 は 10.3〜10.6 点でほぼ一定だった。
- **境界は点数でも一定ではない。** k を 1,024 に固定して n を 10 万 → 80 万にすると、r50（0.01 未満）は 7〜8 → 10〜11 → 12〜18 → 28〜33 点と上がった。quality 則（バッチ 8 分の 1）でも 16〜44 点に上がった。
- **n/k が同じなら境界も同じだった。** n=50k・k=256 は、n=200k・k=1,024 とほぼ一致した（10.2〜11.0 点）。B/n と α0 がほぼ同じ構成である。
- × B/(n·α0) の正規化はばらつきが最も小さいが、quality 則の 1 エポック（44 点）は外れる。この 1 つの比だけでは決まらない（結果 3）。

学習点数の区間ごとの「一度でも下回る」割合（0.01 未満、1 / 3 / 10 エポック。「—」は該当するブロブなし）:

| 実行 | ≤ 10 | 11〜20 | 21〜30 | 31〜60 | 61〜120 | 121〜240 |
|---|---|---|---|---|---|---|
| n=100k | 60 / 56 / 67% | 20 / 5 / 10% | 7 / 1 / 2% | 1 / 0 / 0% | 0% | 0% |
| n=200k（既存） | 69 / 78 / 76% | 26 / 20 / 23% | 8 / 2 / 4% | 2 / 0 / 0% | 0% | 0% |
| n=400k | 100 / 100 / 87% | 52 / 63 / 25% | 17 / 18 / 3% | 2 / 2 / 1% | 0 / 0 / 0% | 0% |
| n=800k | — | 75 / 100 / 100% | 53 / 73 / 76% | 18 / 23 / 18% | 1 / 0 / 1% | 0% |
| quality 則 | 96 / 99 / 99% | 81 / 79 / 52% | 68 / 50 / 10% | 55 / 33 / 2% | 26 / 10 / 0% | 15 / 1 / 0% |

- n=800k の 11〜20 点は 4 個しかない（1 回の学習あたり約 1 個）。
- 240 点を超えるブロブで下回ったものは、どの条件にもなかった。
- n=800k では 31〜60 点のブロブでも 18〜23% が下回った。Medium では 0〜2% だった。quality 則の 1 エポックでは、121〜240 点のブロブでも 15% が下回った。

## 結果 2: 公式の更新式だけのモデルが、境界を実測どおりに再現した

次のモデルで、「一度でも下回る」確率を学習点数ごとに計算した。これはモデルの計算値で、実測ではない。

- ブロブの r 点は、各エポックの並べ替えの中にランダムに散らばるとする（他のブロブの点は混ざらず、自分の点はすべて受け取るとする）。
- 質量の更新は公式の式 N ← (1−α)N + α·n_j とする。初期値は 2^−16、α は公式のコサイン減衰（α0 → 0.1·α0）とする。
- 平均の質量も同じ式でバッチの大きさから更新する。5 回に 1 回の判定で N < 閾値 × 平均かを見る。
- B・α0 は各実行の `runs.csv` の値を使う。各点数で 400 回試行した。

n=800k の予測は、その計測が終わる前に計算して記録した（予測の記録は 2026-11-13 13:06 JST、計測の終了は 13:21 JST。`metadata.json` の `finished_at` による）。

| 実行 | 実測 r50（0.01 未満） | モデル r50 |
|---|---|---|
| n=50k・k=256 | 11.0 / 10.6 / 10.2 | 11.4 / 10.6 / 10.7 |
| n=100k | 7.6 / 6.8 / 8.0 | 7.4 / 6.7 / 7.6 |
| n=200k（既存） | 10.3 / 10.6 / 10.6 | 10.8 / 10.4 / 10.4 |
| n=400k | 16.6 / 18.2 / 12.1 | 16.5 / 18.6 / 11.5 |
| **n=800k（計測前の予測）** | **28.0 / 32.8 / 31.3** | **27.9 / 32.4 / 31.0** |
| quality 則 | 43.9 / 28.3 / 15.5 | 51.1 / 27.0 / 14.8 |

- 18 構成のうち 17 で、モデルと実測の差は相対 6% 以内（最大 1.3 点）だった。外れたのは quality 則の 1 エポック（モデル 51、実測 44）である。この構成は、下回る確率が点数とともにゆっくり下がり、r50 の位置が定まりにくい（実測でも 31〜60 点で 55%、61〜120 点で 26%）。
- モデルには、ブロブの位置・重心どうしの奪い合い・e-means のアルゴリズムの細部が入っていない。それでも境界が合ったので、**点の少ないブロブの唯一の重心の落ち込みは、点がバッチに入るかどうかの偶然と、公式の EMA・判定の間隔だけで説明できる。**
- モデルの読み方としては、境界を決めるのは次の 3 つである。
  1. ステップ幅 α。大きいほど、点が来ない更新が数回続くだけで質量が落ちる。n を増やすと α0 は大きくなる（バッチ則と Equation 6 の組み合わせ）。
  2. 1 バッチに入る点数の期待値。小さいほど、点の来ない更新が続く。
  3. 判定の回数と時期。判定が多いほど、落ち込みを見つける機会が増える（結果 3）。

  エポック数を変えると 1 と 2 が逆向きに動いて相殺し、境界は点数でほぼ一定に見えた。Medium の約 30 点（[findings-revival-lowthr.md](findings-revival-lowthr.md)）は、この相殺の結果だった。

## 結果 3: 下回りの多くは、最初の判定の時点ですでに起きていた

閾値 0 の学習で、単独の重心が一度でも 0.01 未満になったケースのうち、最初の判定（5 回目の更新の後）ですでに 0.01 未満だった割合（1 / 3 / 10 エポック）:

| 実行 | 割合 |
|---|---|
| n=50k・k=256 | 65 / 27 / 42% |
| n=100k | 81 / 44 / 42% |
| n=200k（既存） | 64 / 31 / 35% |
| n=400k | 50 / 23 / 22% |
| n=800k | 46 / 29 / 13% |
| quality 則 | 94 / 83 / 39% |

- 質量の初期値は 2^−16 で、平均よりはるかに小さい。最初の判定までの 5 回の更新で自分のブロブの点が 1 つも来なければ、質量はほぼゼロのまま判定を迎える。
- 最初の判定までに使うデータは、5 × B/n、つまり学習データの 10% / 20% / 82%（throughput 則、1 / 3 / 10 エポック。n=800k の 10 エポックは 41%）である。quality 則の 1 エポックでは 1.3% しかない。
- 例えば 41 点のブロブから、学習データの 1.3% に 1 点も入らない確率は約 0.59 である（41 点 × 1.3% ≈ 0.53 点の期待値からの計算）。quality 則の 1 エポックで、31〜60 点のブロブが閾値によらず約 55% 下回ったこと（0.001 / 0.01 / 0.02 で 54 / 55 / 56%）と同じ程度の値である。
- つまり、低い閾値の復活の一部は「落ち込み」ではなく、「まだ一度も点を受け取っていない重心」を最初の判定で動かしている。これは閾値の大きさでは防げない。

## 結果 4: 閾値 0.01 の復活で失う被覆は、境界の位置に沿って動く

学習中の最後の判定時点で、どの重心からも最寄りとされないブロブの数の差（閾値 0.01 − 閾値 0、同じシードどうしの中央値。1 / 3 / 10 エポック）と、test MSE の差:

| 実行 | 未被覆の増加（合計） | 主な区間 | test MSE の差の中央値 [最小, 最大] |
|---|---|---|---|
| n=50k・k=256 | +8 / +6 / +7 | ≤ 20 点 | +1.4% [−1.1, +4.2] / +0.1% [−0.6, +2.7] / +1.2% [+0.7, +1.7] |
| n=100k | +114 / +85 / +108 | ≤ 10 点（+92〜+110） | +5.8% [+4.7, +8.0] / +2.9% [+1.4, +4.7] / +6.8% [+3.3, +7.5] |
| n=200k（既存） | +70 / +61 / +67 | ≤ 20 点 | +2.7% [+0.2, +4.1] / +2.9% [+0.6, +3.2] / +3.4% [+2.5, +4.0] |
| n=400k | +38 / +41 / +13 | 11〜30 点 | +0.9% [−0.6, +1.5] / +1.2% [+0.7, +1.9] / +0.4% [+0.1, +0.4] |
| n=800k | +22 / +29 / +30 | 21〜60 点 | +0.4% [+0.1, +1.7] / +1.2% [+0.5, +1.6] / +1.2% [+0.6, +2.3] |
| quality 則 | +242 / +184 / +118 | ≤ 60 点 | +23.0% [+16.3, +27.0] / +11.3% [+9.0, +16.6] / +4.6% [+1.8, +6.2] |

- 区間別の内訳と合計は中央値どうしなので、一致しないことがある。
- test MSE の差は、閾値 0 に対する相対値（%）で示した。[findings-revival-lowthr.md](findings-revival-lowthr.md) の表は MSE の差そのもので、単位が異なる。
- 未被覆が増える区間は、結果 1 の境界の位置に沿って動いた。n=800k では 21〜60 点、n=100k では 10 点以下だった。
- 閾値 0.01 の復活は、指数 1.3 の 6 条件・18 構成すべてで、test MSE の中央値を上げた。
- 悪化が最も大きかったのは quality 則の 1 エポック（+23%、復活の延べ数は中央値 1,212 回）だった。n を増やすと、MSE の悪化は小さくなった（n=100k で +2.9〜+6.8%、n=800k で +0.4〜+1.2%）。境界の点数は上がっても、境界より小さいブロブが全体に占める割合が減るためと考えられる（n=800k では 30 点以下のブロブは 93 個、n=100k では 824 個）。
- ブロブの大きさの分布は条件ごとに異なる。k=256 は k=1,024 と比べ、相対的な大きさの分布が違う。そのため、未被覆の数を条件どうしで直接比べることはしない。

## 結論（この条件の範囲に限る）

1. **境界の「約 30 点」は Medium（n=200,000、k=1,024、throughput 則）での値で、条件で動く。** 半数が平均の 0.01 倍を下回る点数（r50）は、k=1,024 で n を 10 万 → 80 万にすると 7〜8 点 → 28〜33 点と上がった。quality 則（バッチ 8 分の 1）では 16〜44 点だった。n/k が同じ n=50k・k=256 では、Medium と同じ 10〜11 点だった。
2. **当初の仮説「1 バッチに入る点数の期待値で決まる」は支持されなかった。** エポック数で B/n が 8 倍変わっても、境界はほぼ動かなかった。
3. **境界は、公式の EMA の式・ステップ幅のスケジュール・5 更新ごとの判定・バッチ則だけのモデルで再現できた。** n=800k は、計測前に記録した予測と実測が 1 点以内で一致した（28 / 32 / 31 点に対して 28 / 33 / 31 点）。点の少ないブロブの唯一の重心が引き剥がされる現象は、点がバッチに入るかどうかの偶然で説明できる。ブロブの配置や重心の奪い合いを持ち出す必要はない。
4. **下回りの 13〜94% は、最初の判定の時点ですでに起きていた。** 質量は 2^−16 から始まり、最初の判定（5 更新後）までに点が来ない重心は、質量がほぼゼロのまま判定を迎える。判定が早い quality 則（学習データの 1.3% の時点）で特に多い。
5. **閾値 0.01 の復活は、指数 1.3 の全条件で test MSE を上げた。** 悪化の大きさは、境界より小さいブロブの数で変わった。quality 則の 1 エポックで +23%、n=800k で +0.4〜+1.2% だった。この悪化は、[findings-imbalanced.md](findings-imbalanced.md) の「指数 1.3 では閾値が低いほど良く、復活なしが最良」と同じ向きである。
6. 本調査は、指数 1.3 の人工データ（d=64）、5 シード、閾値 0.01 と 0 での観察である。指数 1.0 や separated で境界が同じモデルに従うかは確かめていない。モデルは実測の代わりではなく、境界の位置の説明として扱う。

## 再現コマンド

```bash
P="uv run python diagnose_revival.py --profile medium --threads 4 --snapshots --thresholds 0.01 0 --kmeans-niter 0 --dataset imbalanced --imbalance-exponent 1.3"
$P --ntrain 50000 --k 256 --run-name rev_bnd_n50k_k256
$P --ntrain 100000 --run-name rev_bnd_n100k
$P --batch-law quality --run-name rev_bnd_quality
$P --ntrain 400000 --run-name rev_bnd_n400k
$P --ntrain 800000 --run-name rev_bnd_n800k
```

既存の n=200k は `rev_low_imb13`（[findings-revival-lowthr.md](findings-revival-lowthr.md) の再現コマンド）を使った。

## 次の検証候補

- 判定を「質量ゼロが連続したときだけ」や「一定期間の質量の和」で行う場合の比較（本リポジトリの改変。仕組みの確認としてのみ扱う）。結果 3 の「最初の判定で、まだ点を受け取っていない重心」を除けるかも見る。
- 指数 1.0・separated で、同じモデルが境界を説明するか。
- 公開実データ（SIFT1M・DEEP1M）で n・k を振ったときの品質（[README](../README.md) の今後の課題）。真のブロブがないため、ここでの点数の境界は直接は測れない。
