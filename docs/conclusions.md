# 結論: e-means の主張は CPU でどの条件で再現するか

> **下書き（2026-11-13 作成）。** 【計測後に記入】の箇所は、実データで k・n を振った夜間の速度計測の後に埋める。k・n を振った品質は 2026-11-13 日中に `--quality-only` で計測済み（`reports/q_real_*_{k256,k4096,n800k}/`）。それまでの数値はすべて既存のレポートからの転記で、README の 7 節と対応する。

## 対象と範囲

- 対象: `faiss.contrib.e_means.NumpyEmeans`（CPU 実装）。公式ソースは `FAISS_COMMIT` に固定した。比較相手は Faiss の Lloyd 法（`faiss.Kmeans`）である。
- 環境: Intel Core Ultra 7 258V（WSL2、論理コア 6）、特記がなければ 4 スレッド。
- データ:
  - 人工データ 3 種類（gaussian、separated、imbalanced）。Medium は n=200,000、d=64、k=1,024 で、ここから n・k・d を 1 つずつ変えた。
  - 公開実データ 2 種類（SIFT1M d=128、DEEP1M d=96）。n=200,000、k=1,024 を基点に、k=256・4,096 と n=800,000 を 1 つずつ変えた点（品質は計測済み、速度は【計測後に記入】）。
- 判定: test MSE が基準（Lloyd 25 反復）の 1.01 倍以内なら「到達」とする。速度は、作業のない時間帯の計測（CPU の取り合いの検出 0 件）だけを根拠にした。
- 範囲外: 論文の GPU 実験（H100、Flash-KMeans との比較）は再現していない。論文の約 10 倍という実時間の数値は、本検証の対象外である。

## 要約

| 公式の主張 | 本検証の判定 | 根拠 |
|---|---|---|
| Lloyd と比べ、エポック数・実時間とも約 10 倍速い | **比較のしかたによる。** 公式デフォルト対 Lloyd 25 反復では 8〜16 倍で再現した。ただし Lloyd は 5〜10 反復で同じ品質に届くので、そこと比べると約 3〜3.6 倍になる。初期重心を揃えて更新則だけを比べると 1.5〜1.9 倍（実データ 2.7〜2.8 倍）である。d ≤ 16 では Lloyd より遅い | 問い 1 |
| より低い損失 | **データによる。** gaussian と実データでは同等で、10 エポックで Lloyd 25 反復より 0.4〜0.5% 低い（実データ）。不均衡データでは、同じ初期重心の Lloyd に届かない | 問い 2 |
| 追加のハイパーパラメータが不要 | **反例がある。** クラスタ復活の閾値の最良値は分布で異なり、不均衡データでは既定値が劣後の主因だった。低次元では、既定のバッチ則より throughput 則のほうが速い | 問い 3 |

## 問い 1: e-means は Lloyd より速いか

比べ方によって、倍率は 1 桁変わる。

| 比べ方 | Medium（人工、d=64） | 実データ（n=200k、k=1,024） |
|---|---|---|
| 仕様どおりの比較: 公式デフォルトの e-means 対 Lloyd 25 反復 | 12.7〜15.2 倍（gaussian・separated） | 8.0〜16.5 倍 |
| 同手法最短比: Lloyd が同じ品質に届く最短の反復数と比べる | 3.1〜3.6 倍 | 3.1〜3.5 倍 |
| 初期重心を揃えた比較: e-means++ 対 Lloyd++（差は更新則だけ） | 1.8 倍 | 2.7〜2.8 倍 |

- 仕様どおりの比較の大きな倍率は、主に比較相手の弱さによる。Lloyd 25 反復は過剰で、Lloyd は 5〜10 反復で 25 反復と 1% 以内に届く（README 解釈 3）。
- 更新則そのものの差は、d ≥ 64 では規模によらず 1.5〜1.9 倍でほぼ一定だった。k を 16 倍、n を 10 倍、d を 12 倍に変えても、規模とともに伸びる傾向は見えなかった（解釈 8）。
- 公式デフォルト対 Lloyd 25 反復の同手法最短比だけは、k とともに伸びた（k=256 で 2.2 倍、1,024 で 3.1 倍、4,096 で 4.1 倍）。
- **低次元（d ≤ 16）では、ほぼすべての比較で Lloyd より遅い**（d=2 で 0.41〜0.79 倍、d=16 で 0.47〜0.81 倍）。原因は、次元によらない 1 エポックあたりの固定コストである（解釈 9）。
- **スレッドが少ないほど、e-means の倍率は大きい**（公式デフォルト対 Lloyd 25 反復の同手法最短比、gaussian で 1 スレッド 4.16 倍、4 スレッド 3.30 倍）。Lloyd のほうがスレッドの効果が大きいためである。

## 問い 2: 少ないエポックで同等の品質に届くか

- **gaussian、separated、実データでは届く。** 1〜2 エポックで、Lloyd 25 反復の 1.01 倍以内に入った（Medium、実データ、d ≥ 64 の全規模）。
- **ただし、到達と判定された構成に空クラスタが残ることがある。** Medium の separated の 1 エポックでは、公式デフォルトで 41 個、e-means++ で 16 個（/ 1,024）が空だった。d=768 の imbalanced では約半数（495 / 1,024）が空のまま「到達」と判定された（解釈 5・11）。実データでは k=1,024 以下と n=800,000 で空クラスタは 0 だったが、k=4,096 では Lloyd++ 25 反復に 1 エポックで「到達」した構成に 2〜7 個（/ 4,096）が残った。
- **不均衡データ（imbalanced）では届かない。** e-means++ は、同じ初期重心の Lloyd++ に対し、復活が有効なすべての規模の点で未到達だった（1.09〜1.28 倍悪い。解釈 10）。
- 実データの品質差はもともと 1% 程度と小さい。必要エポック数は許容幅に敏感で、基準以下まで求めると 2〜3 エポックが要る（解釈 12・13）。
- 実データで k・n を振った結果（品質のみ、5 シード、4 通りの比較）:

  | 点 | 到達（シード） | 最少エポック（対 Lloyd 25 / Lloyd++ 25） | その構成の空クラスタ | 最良 MSE / 基準 |
  |---|---|---|---|---|
  | SIFT1M k=256 | 全比較 5/5 | 1 / 1 | 0 | 0.996〜0.997 |
  | DEEP1M k=256 | 全比較 5/5 | 1 / 1 | 0 | 0.996 |
  | SIFT1M k=4,096 | 全比較 5/5 | 2 / 1 | 0 / 6〜7 | 0.992〜0.994 |
  | DEEP1M k=4,096 | 全比較 5/5 | 2 / 1 | 0〜1 / 2〜3 | 0.987〜0.991 |
  | SIFT1M n=800,000 | 全比較 5/5 | 1 / 1 | 0 | 0.996 |
  | DEEP1M n=800,000 | 全比較 5/5 | 1 / 1 | 0 | 0.995〜0.997 |

  届かない点はなかった。k を大きくすると、必要エポックが 1 から 2 に増える比較があり（対 Lloyd 25）、1 エポックで止めると空クラスタが残る。一方、最良 MSE が基準を下回る幅は k=4,096 で最も大きい（約 1%）。n を 4 倍にしても到達のしかたは変わらなかった。

## 問い 3: データの分布・次元・クラスタ数で結果は変わるか

変わる。主な要因は次の 3 つである。

1. **クラスタの大きさの偏り。不均衡データでの劣後の主因は、クラスタ復活（`unused_threshold`、既定 0.1）だった。**
   - 復活を無効にすると、Lloyd++ との差は 1.24 倍から 1.016 倍に縮んだ。一方、均等な大きさの separated では、復活があるほうが良い（0.866 対 1.009）（解釈 1）。
   - 復活は、点の少ない真のクラスタから唯一の重心を引き剥がし、すでに重心のある大きなクラスタへ移していた（解釈 14・16・18）。
   - 引き剥がされるのは、点の少ないクラスタの唯一の重心である。点がバッチに入らない更新が続くと、質量が判定時に一時的に閾値を下回る。公式は一度でも下回れば復活させるので、閾値を下げても止まらない（解釈 16〜18）。
   - 引き剥がされるクラスタの点数の境界は n とバッチ則で変わり、公式の EMA と判定の間隔だけのモデルで説明できた（解釈 19）。
   - 最良の閾値は分布で異なり、向きも逆だった（指数 1.3 では復活なし、指数 1.0 では 0.001〜0.02、separated では既定の 0.1。解釈 17）。**「追加のハイパーパラメータ不要」という主張への反例である。**
2. **次元。d ≤ 16 では遅い**（問い 1）。公式デフォルトが d ≤ 16 で選ぶ quality 則のバッチは、1 エポックを重くする。throughput 則を明示すると、d=16 では Lloyd 25 反復より速くなった（1.10〜2.25 倍）。d=2 では遅いままだった。
3. **クラスタ数 k。** 公式デフォルト対 Lloyd 25 反復の倍率は、k とともに伸びた（問い 1）。初期重心を揃えた比較では、ほぼ一定だった。

なお、6 スレッドでは品質がビット単位で一致しなかった（e-means で最大 1.4%）。1% の判定境界付近の結果は、スレッド数に依存しうる。

## 問い 4: 導入を検討する価値はあるか（本検証の条件の範囲で）

**検討する価値があるのは、次の条件がそろう場合である。**

- 高次元（d ≥ 64 で確認。d=16 は throughput 則を明示した場合のみ）。
- クラスタの大きさが極端に偏っていない。実データ（SIFT1M・DEEP1M）はこれに当たり、k=256〜4,096、n=200,000〜800,000 でも品質は届いた（k=4,096 では 2 エポック、または空クラスタを数個許す）。
- 比較相手が Lloyd を必要以上に回している（25 反復など）。そうでなければ、実質の利得は約 1.5〜3.6 倍である（同手法最短比と、初期重心を揃えた比較の範囲）。

**注意が必要な点:**

- **初期化。** 公式デフォルト（ランダム初期化）は品質で損をする。一方 k-means++ 初期化は時間がかかり、e-means++ の 1 エポックの時間の約 7 割を占める（解釈 2）。
- **空クラスタ。** MSE だけで判断せず、空クラスタ数も確認する（解釈 5・11）。
- **不均衡データ。** クラスタの大きさが大きく偏るデータでは、既定の復活の閾値が品質を下げる。閾値の調整が要るが、最良値は分布で異なる（問い 3）。
- **低次元（d ≤ 16）の CPU では勧めない。**
- GPU 実装（論文の主対象）は、本検証の範囲外である。

## 制約

README の 8 節を参照。主なものは次のとおり。

- CPU・WSL2 上の、同じマシン内での相対比較である。時間は夜によって数％ずれ、倍率は最大で約 12% ずれた。
- シード数は 3〜5 である。
- 人工データは 3 種類である。実データは 2 種類で、どちらも画像・汎用の埋め込みに近いデータであり、テキスト埋め込みなどは見ていない。
- 規模は 1 回に 1 要因だけを変えた。要因間の相互作用は見ていない。

## 未実施（今後の課題）

README の 9 節を参照。結論の向きを変えると考えている課題はない。そう判断した理由は次のとおり。

- k = 16,384 以上: 倍率は k とともに伸びる傾向だったため、主張により近づく可能性がある。
- GPU での再現: 論文の主対象である。
- 低次元の固定コストの内訳: 遅さの原因の説明で、遅いという結論は変わらない。
- 復活の仕組みのさらなる確認: 劣後の主因の特定は済んでいる。
