# 調査: 低い閾値（0.001〜0.02）で復活させられる重心は何か

実施日: 2026-11-13 / 計測コード: `8561038`（全実行 `repo_dirty: false`、公式ソースはピン留めの SHA と一致）/ 4 スレッド / **品質専用の診断**（日中に実行。時間は記録していない）

[findings-imbalanced.md](findings-imbalanced.md) の閾値の掃引で、2 つの点が未検証のまま残った。

- 結論 11: 指数 1.3 では、閾値 0.02 以下を下回る真のクラスタが 1 つもない。それでも閾値 0.001 で、1 回の学習あたり延べ 164〜231 回の復活が起きた。標的は何か。
- 結論 12: 低い閾値の復活は、指数 1.0 では閾値 0 より良く（5 シードとも）、指数 1.3 では悪い。この符号の違いはなぜか。

## 方法

- `diagnose_revival.py --snapshots` で、閾値 0.02 / 0.01 / 0.001 / 0 を実行した。公式 `NumpyEmeans` のサブクラスを通して学習し、復活の判定ごとに全重心の状態を記録した（[findings-revival-noise.md](findings-revival-noise.md) と同じ記録）。公式コードは改変していない。判定を止める改変（`--warmup-checks`）も使っていない。
- 条件は以前の診断と同じにした。
  - d=64、Medium（n=200,000、k=1,024）の imbalanced（指数 1.3、1.0）と separated。
  - 5 シード、e-means++、1 / 3 / 10 エポック、Lloyd++25 の参照付き。
- **記録しても学習は変わらない。** e-means++ の全行が、閾値の掃引の実行（`q_imb_thr{002,001,0001,0}`、`q_imb_exp10_thr*`、`q_sep_thr*` の 1 / 3 / 10 エポック）と、test / train MSE・復活の延べ数でビット単位で一致した。閾値 0、Lloyd++25、初期値の行は、`rev_snap_*` と test / train MSE・未被覆ブロブで一致した。1 データあたり 85 行で、不一致は 0 行だった。
- レポート: `reports/rev_low_imb13/`、`reports/rev_low_imb10/`、`reports/rev_low_sep/`。下の表はレポートにない集計で、`results/<run>/events.csv` と `snapshots.csv`（Git 管理外、1 データあたり約 76〜92MB）から計算した。

### 集計の定義

既存の定義（標的・共有ブロブ上・単独など）は [findings-revival.md](findings-revival.md) を参照。本調査で加えた量は次のとおり。

| 量 | 定義 |
|---|---|
| ブロブの学習点数 | 真のブロブから生成された学習データの行数（`data.synthetic_truth` の `train_group` を数えたもの）。平均は約 195 点 |
| 単独（≤ 10 点）など | 標的が単独で、そのブロブの学習点数が 10 点以下などのもの |
| 捕捉率 | 判定時に、標的のブロブの学習点のうち、標的が最寄りの重心になっている割合（[findings-revival-noise.md](findings-revival-noise.md) と同じ） |
| 最後の判定での未被覆 | 学習中の最後の判定時点で、どの重心からも最寄りとされないブロブ。学習点数の区間ごとに数えた。学習後の未被覆ブロブ数（`runs.csv`）との差は、構成ごとの中央値で 0〜2 個（個々の学習では −5〜+3 個）だった |
| 一度でも下回る | 閾値 0（復活なし）の学習で、全判定を通じて同じブロブの唯一の重心だった重心のうち、どれかの判定で質量 / 平均が各閾値を下回ったものの割合 |

60 点を超えるブロブ（3 データとも）と separated の全ブロブでは、0.02 未満に下がった唯一の重心はなかった（0%）。

- 学習点 10 点以下のブロブの唯一の重心は、質量の中央値が平均の約 0.04 倍あり、ブロブの真の大きさと一致した。それでも 31〜48% が、学習中に一度は平均の 0.001 倍（約 0.2 点）を下回った。0.01 倍では 69〜78% が下回った。
- 1 / 3 / 10 エポックのバッチは 4,096 / 8,192 / 32,768 点で、学習データの 2〜16% にあたる。10 点のブロブからバッチに入る点数の期待値は 0.2〜1.6 点で、点が 1 つも入らない更新が続くことがある。その間に EMA 質量はゼロに近づくと考えられる（期待値からの説明で、更新ごとの点数は記録していない）。
- これは、[findings-revival-noise.md](findings-revival-noise.md) の「閾値のすぐ上のブロブは一度は閾値を下回る」と同じ現象である。下回りの頻度は「閾値に対する比」より「ブロブの点数」で決まり、閾値を 100 分の 1 にしても、点の少ないブロブでは止まらない。

## 結論（この条件の範囲に限る）

1. **結論 11 の標的を特定した。低い閾値の標的は 2 種類だった。**
   - 1 つは、他の重心とブロブを分け合い、点をほとんど受け取らない重心である（指数 1.3 で 63〜89%、指数 1.0 で 94〜100%、separated で 100%）。
   - もう 1 つは、学習点 30 点以下のブロブの唯一の重心である（指数 1.3 で 11〜37%）。点が少ないため、自分のブロブを捕捉していても、判定の時点で質量がほぼゼロになる。
   - 「真のクラスタが閾値を下回る」ことで起きる復活ではない。閾値 0.02 以下を下回る真のクラスタは、どの分布にもない。
2. **結論 12 の符号の違いは、30 点以下のブロブの有無で説明できる。**
   - 指数 1.0 では、最小のブロブが 15 点で、30 点以下は 158 個（指数 1.3 では 697 個）。唯一の重心が閾値 0.02 未満に下がることは少ない（11〜20 点のブロブは 12 個以下で 11〜27%、21〜30 点では 3〜10%）。復活は、ほぼ重複した重心の付け替えとして働く。未被覆ブロブは閾値 0 より 3〜11 個減り、test MSE は全構成・全シードで下がった。
   - 指数 1.3 では、10 点以下のブロブが 274 個ある。その唯一の重心の 31〜48% が、閾値 0.001 でも一度は下回る。復活のたびに、そうしたブロブから重心がなくなる。未被覆ブロブの増加（+18〜+100）は、ほぼすべて 30 点以下のブロブで起きた。重複の付け替えによる改善を、この損失が上回った。
   - separated は最少のブロブでも 155 点で、単独の標的は 0 件だった。復活は未被覆ブロブを 14〜29 個減らした（[findings-revival.md](findings-revival.md) の結論 5 と同じ傾向）。
3. **閾値を下げても、点の少ないブロブからの引き剥がしは止まらない。** 公式の判定は、質量が一度でも閾値を下回れば復活させる。点の少ないブロブでは、ゼロに近い落ち込みが閾値の大きさによらず起きる。閾値の比で調整できるのは、点数が十分あるブロブだけである（[findings-revival-noise.md](findings-revival-noise.md) の結論 2 を、低い閾値に広げたもの）。
4. 本調査は、ブロブの点数の分布が異なる 3 つの人工データ（d=64、k=1,024、n=200,000）だけでの観察である。「30 点」という境界は、本条件のバッチの大きさ（学習データの 2〜16%）と EMA の設定に依存すると考えられ、ほかの n・k・バッチでの値は確かめていない。
   - **→ 確認済み（2026-11-13、[findings-revival-boundary.md](findings-revival-boundary.md)）。** 境界は条件で動いた。半数が平均の 0.01 倍を下回る点数は、k=1,024 で n=100,000 → 800,000 にすると 7〜8 → 28〜33 点、quality 則では 16〜44 点だった。1 バッチに入る点数の期待値では揃わなかった。公式の EMA の式・ステップ幅・判定の間隔だけのモデルで再現でき、n=800,000 は計測前の予測と一致した（`model_revival_dip.py`）。
